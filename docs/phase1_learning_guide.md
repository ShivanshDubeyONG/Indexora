# Phase 1 Learning Guide: Distance Kernels & Deterministic Top-k

Welcome to Phase 1 of Indexora! In this phase, you will build the foundational mathematical engine that powers all vector search: **pairwise distance calculation** and **top-$k$ neighbor selection**.

Before writing code, study this guide to build a rock-solid mental model of what these operations do, why exact calculation matters, and where subtle edge-case bugs hide.

---

## 1. Core Concepts

### What is a Vector?
In machine learning and information retrieval, a **vector** is an ordered sequence of real numbers representing an item (a document chunk, an image embedding, an audio fingerprint, or a user profile) in a geometric space. 

For example, a sentence embedding model might convert the text *"vector search from scratch"* into a sequence of numbers like `[0.042, -0.185, 0.912, ...]`. Each number in that sequence represents the coordinate or projection of that sentence along a specific conceptual axis.

### What Does Vector Dimension ($d$) Mean?
The **dimension** $d$ is the number of elements (coordinates) in the vector. 
- If $d = 2$, each vector is a point on a 2D Cartesian plane $(x, y)$.
- If $d = 128$ (e.g., classical SIFT descriptors), each vector lives in 128-dimensional space.
- If $d = 384$ or $768$ (e.g., MiniLM or BERT embeddings), each vector lives in a high-dimensional semantic latent space.

In Indexora, all vectors in a given index must share the exact same dimensionality $d$.

### What Does Squared-L2 Distance Measure?
The **squared Euclidean distance** (squared $L_2$ distance) between a query vector $q$ and a database vector $x$, both of dimension $d$, is defined as:

$$d^2(q, x) = \sum_{j=1}^{d} (q_j - x_j)^2$$

It calculates the square of the straight-line geometric distance between the two points in $d$-dimensional space.

### Why Smaller Distances Indicate Closer Vectors
In geometric space, two identical points have a distance of zero:
$$d^2(x, x) = \sum_{j=1}^{d} (x_j - x_j)^2 = 0$$

As coordinates diverge, the differences $(q_j - x_j)$ grow, and their squares $(q_j - x_j)^2$ grow non-negatively. Therefore:
- **Smaller distance** $\implies$ closer in space $\implies$ higher geometric similarity.
- **Larger distance** $\implies$ farther apart $\implies$ lower similarity.

We prefer squared-$L_2$ over standard Euclidean distance ($\sqrt{\sum (q_j - x_j)^2}$) because the square root is a strictly monotonic function for non-negative values. Omitting $\sqrt{\cdot}$ does not change the ranking of candidates and saves considerable computation.

### Why Exact Search is Our Correctness Reference
Approximate Nearest Neighbor (ANN) algorithms (such as IVF, PQ, and HNSW) make structural compromises: they skip candidate vectors or compress coordinates to achieve sub-millisecond latencies. 

To scientifically evaluate an ANN algorithm's recall (how many true neighbors it successfully found), you **must** compare its output against an infallible ground truth. That ground truth is generated by **exact flat search**: an exhaustive, brute-force scan evaluating every single vector using our reference distance kernel.

### Why We Need Deterministic Tie-Breaking
In real-world data and benchmark tests:
1. Duplicate vectors can exist in the dataset.
2. Distinct vectors can be equidistant from a query (e.g., points symmetric about the query).
3. Floating-point round-off can cause two distinct pairs to evaluate to the exact same float32 distance.

If ties are resolved arbitrarily (by whatever order the CPU or NumPy's partition algorithm happened to place them in memory), tests will be flaky and benchmark comparisons between algorithms will not be reproducible. 

To eliminate ambiguity, Indexora enforces a strict compound ordering rule:
$$\text{Rank by: } (d^2(q, x), \text{ID})$$
If distances are identical, the vector with the smaller numerical `int64` ID wins.

## 2. A Hand-Worked Example

Let us walk through a concrete example by hand in 2D space ($d = 2$).

### The Database
Suppose our index stores $N = 4$ vectors with unique stable IDs:

| Stable ID | Coordinates $(x_0, x_1)$ | Note |
| :--- | :--- | :--- |
| **101** | `[1.0, 2.0]` | Point A |
| **102** | `[4.0, 6.0]` | Point B |
| **103** | `[2.0, 1.0]` | Point C |
| **104** | `[1.0, 2.0]` | Point D (Exact duplicate of A) |

### The Query
We receive query vector $q = [1.0, 1.0]$ and wish to find the **top $k = 2$** nearest neighbors.

### Step 1: Compute Distances by Hand
1. **Distance to ID 101:**
   $$d^2(q, x_{101}) = (1.0 - 1.0)^2 + (1.0 - 2.0)^2 = (0.0)^2 + (-1.0)^2 = 0.0 + 1.0 = \mathbf{1.0}$$

2. **Distance to ID 102:**
   $$d^2(q, x_{102}) = (1.0 - 4.0)^2 + (1.0 - 6.0)^2 = (-3.0)^2 + (-5.0)^2 = 9.0 + 25.0 = \mathbf{34.0}$$

3. **Distance to ID 103:**
   $$d^2(q, x_{103}) = (1.0 - 2.0)^2 + (1.0 - 1.0)^2 = (-1.0)^2 + (0.0)^2 = 1.0 + 0.0 = \mathbf{1.0}$$

4. **Distance to ID 104:**
   $$d^2(q, x_{104}) = (1.0 - 1.0)^2 + (1.0 - 2.0)^2 = (0.0)^2 + (-1.0)^2 = 0.0 + 1.0 = \mathbf{1.0}$$

### Step 2: Form Composite Keys $(d^2, \text{ID})$
- ID 101: `(1.0, 101)`
- ID 102: `(34.0, 102)`
- ID 103: `(1.0, 103)`
- ID 104: `(1.0, 104)`

Notice there is a **three-way tie** at distance $1.0$ (IDs 101, 103, and 104)!

### Step 3: Sort by Composite Key
Sorting ascending by distance, then by ID:
1. `(1.0, 101)`
2. `(1.0, 103)`
3. `(1.0, 104)`
4. `(34.0, 102)`

### Step 4: Select Top $k = 2$
Taking the first 2 candidates yields:
- **Rank 1:** ID `101` (distance `1.0`)
- **Rank 2:** ID `103` (distance `1.0`)

*(ID 104 is omitted because, although its distance is 1.0, its ID 104 is greater than 103).*

## 3. The Reference Distance Kernel Contract

The reference distance kernel is the **correctness oracle** for Indexora. Every other distance calculation in the engine will be validated against this kernel.

### Contract Specification
- **Function Concept:** `pairwise_squared_l2_ref(queries, database)`
- **Inputs:**
  - `queries`: 2D array of shape `(Q, d)` or 1D array of shape `(d,)`
  - `database`: 2D array of shape `(N, d)`
  - Data types: `float32` (or compatible floating point)
- **Outputs:**
  - If batched: 2D array of shape `(Q, N)` with `dtype=float32` (or `float64` accumulator downcast)
  - If single query: 1D array of shape `(N,)`
- **Validation & Error Handling:**
  - Dimension mismatch ($d_q \ne d_{db}$): Must raise `ValueError`.
  - Non-2D shapes (or improper dimensionalities): Must raise `ValueError`.
  - Empty database ($N = 0$): Return empty distance array of shape `(Q, 0)`.
  - Non-finite values (`NaN`, `Inf`): Must reject or handle cleanly as specified.

### Reference Kernel Pseudocode
```text
FUNCTION pairwise_squared_l2_ref(Q, X):
    VALIDATE Q is 2D and X is 2D
    VALIDATE Q.dimension == X.dimension
    VALIDATE all values in Q and X are finite

    LET num_queries = Q.shape[0]
    LET num_vectors = X.shape[0]
    LET d = Q.shape[1]

    INITIALIZE distances matrix D of shape (num_queries, num_vectors) with zeros (float64 precision)

    FOR q FROM 0 TO num_queries - 1:
        FOR i FROM 0 TO num_vectors - 1:
            LET sum_sq = 0.0 (float64)
            FOR j FROM 0 TO d - 1:
                LET diff = float64(Q[q, j]) - float64(X[i, j])
                sum_sq = sum_sq + diff * diff
            D[q, i] = sum_sq

    RETURN D cast to float32
```

## 4. Deterministic Top-$k$ Selection

### Why Not Just Sort Everything?
Sorting all $N$ distances costs $\mathcal{O}(N \log N)$ operations. When $N = 1,000,000$ and $k = 10$, sorting all million items wastes enormous CPU time.

### Partial Selection with `argpartition`
NumPy provides `np.argpartition(distances, kth=k-1)`, which uses Introselect to partition the array in $\mathcal{O}(N)$ average time. The smallest $k$ items are moved to the first $k$ positions, but:
1. They are not internally sorted within the first $k$ elements.
2. **Critical Flaw at Tie Boundaries:** If multiple items have the exact same distance as the item at index $k-1$, `argpartition` makes an arbitrary choice about which of those tied items is included in the partition and which is left out.

### The Deterministic Top-$k$ Invariant
To ensure strict reproducibility:
1. If $k \ge N$, return all $N$ items sorted by `(distance, ID)`.
2. When performing partial selection, any candidate whose distance equals the boundary distance must be inspected and tie-broken by ID before finalizing the top $k$.
3. The final returned array must be sorted in strictly ascending `(distance, ID)` order.

A popular formula for fast distance computation via matrix multiplication is:
$$\|q - x\|^2 = \|q\|^2 - 2 q^T x + \|x\|^2$$
Consider $q = [1000.0, 1000.0]$ and $x = [1000.0, 1000.001]$:
1. What is the exact squared distance $(1000.0 - 1000.0)^2 + (1000.0 - 1000.001)^2$?

## 6. Phase 1 Acceptance Criteria

Before marking Phase 1 complete, your implementation must satisfy the following acceptance gates:

1. **Numerical Accuracy:** Reference distance kernel produces exact results matching hand-calculated test vectors.
2. **Dimension Invariance:** Input shape validation rejects mismatched dimensions ($d_q \ne d_{db}$) and malformed inputs with descriptive `ValueError`.
3. **Deterministic Tie-Breaking:** For identical vectors or equidistant points, output ordering strictly follows ascending `(distance, ID)`.
4. **Boundary Ties:** Ties occurring exactly across the $k$-th selection boundary are resolved correctly according to the stable ID policy.
5. **Edge Cases:** Clean, documented behavior for $k = 1$, $k = N$, $k > N$, and empty inputs.
6. **Isolation:** Reference kernel operates without external library dependencies (only NumPy).

## Answer Key for Learning Exercises

### Answer 1
1. Difference:
   - Component 0: $(2.0 - (-1.0)) = 3.0 \implies 3.0^2 = 9.0$
   - Component 1: $(3.0 - 3.0) = 0.0 \implies 0.0^2 = 0.0$
   - Component 2: $(-1.0 - 3.0) = -4.0 \implies (-4.0)^2 = 16.0$
   - Sum: $9.0 + 0.0 + 16.0 = \mathbf{25.0}$.
2. Yes, symmetry always holds because $(q_j - x_j)^2 = (-(x_j - q_j))^2 = (x_j - q_j)^2$.

### Answer 2
1. Exact calculation:
   $0^2 + (-0.001)^2 = 0.000001 = 1.0 \times 10^{-6}$.
2. In single precision `float32`, $\|q\|^2 = 1000^2 + 1000^2 = 2{,}000{,}000$. Single precision only provides $\approx 7$ decimal digits of mantissa precision. When subtracting two numbers around $4 \times 10^6$ to compute a residual of $10^{-6}$, severe **catastrophic cancellation** occurs. The computed value can easily become $-0.0001$ or slightly negative. That is why fast BLAS kernels must clamp small negative numbers to zero and must be verified against the reference kernel oracle!

### Answer 3
1. The distances are sorted: 2.0, 2.0, 2.0, 4.0, 5.0. For $k = 2$, the boundary distance is `2.0`.
2. IDs 20, 30, and 40 are all tied at distance `2.0`.
3. Under ascending `(distance, ID)` ordering:
   Candidate pairs are: `(2.0, 20)`, `(2.0, 30)`, `(2.0, 40)`.
   The two lowest composite keys are `(2.0, 20)` and `(2.0, 30)`.
   Therefore, IDs `[20, 30]` must be returned.

### Answer 4
1. When $k > N$: Return all $N$ available items in sorted order (do not crash or pad with invalid IDs).
2. When $k = 0$: Return empty result arrays (0 items).
3. When $k < 0$: Raise a `ValueError("k must be non-negative")`.
4. When $N = 0$: Return empty result arrays.

### Answer 5
1. Sorting $100,000$ items takes $\approx 100,000 \times \log_2(100,000) \approx 1.66 \times 10^6$ operations. Only 10 items are needed, so $99.99\%$ of the sorting work is discarded.
2. **Comparison:**
   - **Approach A (`argpartition`):** $\mathcal{O}(N)$ selection in vectorized C/NumPy code. Extremely fast in NumPy, but requires careful handling of boundary ties if multiple items match the boundary value.
   - **Approach B (Heap of size $k$):** $\mathcal{O}(N \log k)$ operations. Minimal extra memory ($\mathcal{O}(k)$), but in pure Python, a loop of $100,000$ heap pushes is much slower than vectorized NumPy operations due to Python interpreter overhead.
